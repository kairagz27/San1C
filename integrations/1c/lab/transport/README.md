# Локальный HTTPS-стенд San1C для проверки 1С

Экземпляры San1C запускаются в Docker Desktop на Windows. Команды ниже выполняются в PowerShell из корня репозитория. Нужны Python 3.10+ с командой `py` и Compose с поддержкой `!reset`. Порт основного демо 8088 остаётся доступным.

| Назначение | Проект Compose | Рабочие продажи | Профиль |
| --- | --- | --- | --- |
| Выгрузка из файловой базы 1С | san1c-lab-native | https://localhost:8446/#/live/sales | san1c-file-lab-v1 |
| Проверка HTTP-контракта из файла | san1c-lab-fixture | https://127.0.0.1:8447/#/live/sales | educational-documents-v1 |
| Две недели из 1С, две точки и планировщик | san1c-lab-pilot | https://localhost:8448/#/live/sales | san1c-file-lab-v1 |

У каждого экземпляра собственные PostgreSQL 17, том с фактами, сеть Compose, пароль владельца, токен загрузки и удостоверяющий центр. Caddy принимает HTTPS на loopback Windows и проксирует запросы в приложение. API и веб-интерфейс имеют общий origin. Файловая 1С запускается на этом же компьютере. Для серверного варианта адрес и доверие настраивает администратор сервера 1С.

## Запуск

```powershell
py -3 -X utf8 integrations/1c/lab/transport/lab.py up native
py -3 -X utf8 integrations/1c/lab/transport/lab.py up fixture
py -3 -X utf8 integrations/1c/lab/transport/lab.py up pilot
py -3 -X utf8 integrations/1c/lab/transport/lab.py status native
```

Первый запуск создаёт тестовые секреты. Повторный использует уже созданные и пересобирает приложение из текущего checkout. Строки отчётов и ключи удостоверяющих центров сохраняются в именованных томах. При первом старте нативного экземпляра ожидайте для 16 ноября статус `missing` и пустой диапазон подтверждённых дат. Демо-набор внутри каждого экземпляра доступен отдельно через `/#/demo/sales`.

Сервер читает учебный `integrations/1c/profiles/educational/experiment.json` для нативного эксперимента. Чтобы явным образом выбрать проверенный профиль, передайте `up native --profile <путь-к-json>`. Каталог с JSON и его шаблоном монтируется в приложение только для чтения. Выбранный профиль и шаблон должны совпадать с макетами внешней обработки.

## HTTPS и параметры обработки

| Параметр | Значение нативного эксперимента |
| --- | --- |
| Хост и порт | `localhost`, `8446` |
| Адрес загрузки | `https://localhost:8446/api/import/days` |
| Проверка профиля и токена | `https://localhost:8446/api/import/check` |
| Период | начало и конец 16.11.2026 |
| Корневой сертификат PEM | `%LOCALAPPDATA%\San1C\lab\transport\native\ca.pem` |
| Тестовый токен | поле `upload_token` в `%LOCALAPPDATA%\San1C\lab\transport\native\credentials.json` |
| Пароли веб-интерфейса | поля `owner_password` и `admin_password` в том же локальном файле |

Для `pilot` используются порт 8448 и каталог `%LOCALAPPDATA%\San1C\lab\transport\pilot`. Инструмент создаёт каталог с ACL текущего пользователя Windows и SYSTEM. Посмотрите секреты в локальном редакторе, когда нужно заполнить форму. В контейнер San1C передаются хеши. Caddy хранит закрытые ключи в приватном томе своего Compose-проекта. На хост копируется публичный корень. Учебный сценарий передаёт полный путь к `ca.pem` в серверный вызов обработки. В обычной форме можно указать этот же путь к CA. При пустом поле применяются системные корни. Учётной записи, от которой выполняется BSL, нужен доступ к соответствующему УЦ.

TLS-клиент скрипта проверяет имя сервера и цепочку до PEM выбранного экземпляра. Профиль Firefox, описанный ниже, доверяет этому CA в пределах собственного хранилища. Системное хранилище сертификатов Windows при работе со стендом не изменяется.

## Контрольная HTTP-фикстура

```powershell
py -3 -X utf8 integrations/1c/lab/transport/lab.py send-fixture
py -3 -X utf8 integrations/1c/lab/transport/lab.py status native
```

Команда `send-fixture` отправляет `day-2026-11-16.json` только на порт 8447. Она посылает два одинаковых запроса с токеном загрузки, датой и меткой формирования, входит в отдельную веб-сессию администратора, проверяет покрытие рабочего дня и четыре показателя в API отчёта. Для свежей базы ответы идут в порядке `accepted`, `unchanged`. При дальнейшем повторе оба ответа равны `unchanged`.

| Срез за 16.11.2026 | Продажи с НДС, ₸ | Возвраты с НДС, ₸ | Выручка, ₸ | Документы продажи |
| --- | ---: | ---: | ---: | ---: |
| Все точки | 10 000,00 | 2 000,00 | 8 000,00 | 1 |
| Учебная точка | 10 000,00 | 2 000,00 | 8 000,00 | 1 |

Для отдельной повторной сверки уже загруженных фактов выполните `lab.py verify fixture`. После реальной выгрузки из обработки выполните `lab.py verify native`. Обе команды только читают отчёты. Нативная сверка выбирает известный UUID учебной точки в файловой базе. HTTPS и квитанция по JSON-фикстуре подтверждают транспорт и расчёт San1C. Исполнение запроса и сборка обработки проверяются отдельно на платформе 1С.

## Сверка в браузере

Для автоматической проверки понадобятся Playwright и его Firefox. При первом создании профиля вспомогательный контейнер получает подписанный пакет `nss-tools` из репозитория Alpine. Импорт сертификата происходит в отдельную базу NSS, созданную только для одного адреса лаборатории.

```powershell
py -3 -m venv .venv
.\.venv\Scripts\python -m pip install playwright
.\.venv\Scripts\python -m playwright install firefox
.\.venv\Scripts\python -X utf8 integrations/1c/lab/transport/browser.py fixture
```

Если `.venv` уже создан, начните со второй команды. Скрипт открывает «Продажи» в новом профиле, входит как тестовый владелец, устанавливает период и фильтр точки, читает четыре значения карточек и проверяет строку таблицы. Скриншот записывается в `.verification/1c-lab/fixture-sales.png`. Для экрана после нативной выгрузки замените `fixture` на `native`. Можно выбрать другой путь флагом `--screenshot`.

Для самостоятельной проверки в обычном Firefox выполните следующие команды. Параметр `--prepare-only` подготавливает отдельный каталог с публичным CA. Выберите 16.11.2026 в обеих границах произвольного периода и «Учебная точка» в фильтре.

```powershell
$labProfile = py -3 -X utf8 integrations/1c/lab/transport/browser.py fixture --prepare-only
& "$env:ProgramFiles\Mozilla Firefox\firefox.exe" -no-remote -profile "$labProfile" "https://127.0.0.1:8447/#/live/sales"
```

Для нативного экрана используйте `browser.py native --prepare-only` и `https://localhost:8446/#/live/sales`.

## Результат проверки 23 ноября 2026 года

В экземпляре `fixture` API вернул `accepted` и `unchanged` для двух одинаковых снимков за 16 ноября. Запросы по всем точкам и с фильтром `lab-store` подтвердили все четыре значения контрольной таблицы. Firefox открыл защищённую рабочую страницу по HTTPS, выполнил вход и показал эти же четыре значения. На графике видна одна подтверждённая дата. Предыдущий день для сравнения отсутствует. Снимок экрана сохранён в `.verification/1c-lab/fixture-sales.png`.

Перед нативной выгрузкой день 16 ноября имел статус `missing`. Затем клиент 1С 8.5.1.1343 дважды передал по HTTPS снимок в `native` с профилем `san1c-file-lab-v1`. Обе квитанции получили HTTP 200 `accepted`, день перешёл в `confirmed`. В рабочей базе остались один снимок и две строки. В Firefox после повтора видны 10 000 ₸ продаж, 2 000 ₸ возвратов и 8 000 ₸ выручки. Каждый HTTPS-стенд отклонил проверку с корневым сертификатом соседнего стенда. [Протокол и квитанции](../first-run.md).

## Остановить стенд

```powershell
py -3 -X utf8 integrations/1c/lab/transport/lab.py stop native
py -3 -X utf8 integrations/1c/lab/transport/lab.py stop fixture
py -3 -X utf8 integrations/1c/lab/transport/lab.py stop pilot
```

Повторите соответствующую команду `up`, чтобы продолжить с теми же сертификатами и данными.
